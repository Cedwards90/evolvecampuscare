## Goal

Reports should clearly identify the organization the data belongs to, while keeping "Generated by Evolve Foundation" as a separate platform attribution. Apply to the on-screen report, PDF, CSV, and bulk exports for Student Progress Reports, and to the Interaction Report exports.

Scope is limited to report headers/footers/metadata and the data needed to feed them. No business logic, RLS, schema, or unrelated UI changes.

## Org identity rules

- **Single-student report:** show the student's own organization in the report header (name from `training_organizations.name` via `profiles.organization_id`).
- **Bulk export:** if filter restricts to exactly one org, show that org's name. If multiple orgs are present in the result set, show "Multiple organizations (N)". If none, show "No organization".
- Logo: skipped per user direction. Header uses org name only.
- Platform attribution: footer of every PDF and a metadata row in every CSV reads `Generated by Evolve Foundation — {generatedAt}` and stays even when an org is shown. The existing "Confidential — Evolve Foundation • Page X of Y" footer is reworded so org identity sits in the body and Evolve attribution sits in the footer.

## Files to change

### Data layer (additive only)

1. **`src/hooks/useStudentProgressReport.ts`**
   - Extend `StudentProgressReport` with `organization: { id: string; name: string } | null`.
   - In the existing fetch, after loading the student profile, if `profile.organization_id` is set, fetch `training_organizations(id, name)` and attach. Falls back to `null` if missing/suspended.
   - No change to existing query keys or RLS calls; org table is already readable by authenticated users.

2. **`src/pages/StudentProgressReport.tsx`**
   - In `fetchReportFor` (used for bulk), mirror the same org lookup so each report entry carries its org. Batched into the existing `Promise.all`.
   - Compute a `bulkOrgLabel` from the entries (single org name vs "Multiple organizations (N)") and pass to `exportBulkStudentProgressPdf` / `…Csv`.

### Export layer (the meat of the change)

3. **`src/lib/studentProgressExport.ts`**
   - New helper `drawReportHeader(doc, { title, orgName, subtitleLines })` — renders the forest-green band with:
     - Line 1 (large, white): org name if present, else "Evolve Foundation Student Progress".
     - Line 2 (small, white): report title.
   - New helper `drawReportFooter(doc, generatedAt)` — replaces existing `drawFooter`. Two-line footer centered:
     - `Generated by Evolve Foundation` (always)
     - `Generated {date} • Page X of Y • Confidential` (always)
   - Update `exportStudentProgressPdf` to call the new header/footer with the org from `r.organization`, and to include a "Report details" mini-table at the top of the body showing: Organization, Student, Case manager, Reporting period (from–to), Generated date.
   - Update `exportBulkStudentProgressPdf` signature to accept `{ rangeLabel, orgLabel }`. Cover page lists Organization, Reporting period, Generated date, total students. Per-student pages each show that student's own org in the body details block (header keeps the bulk org label).
   - Update `buildCsv` so the first section becomes `Report Details` with rows: Organization, Student, Case Manager, Period From, Period To, Generated At, Generated By = "Evolve Foundation". Update `exportBulkStudentProgressCsv` to prepend a `### Report Details` block with the bulk org label, period, generated date, and `Generated By = Evolve Foundation`.

4. **`src/lib/reportExport.ts`** (Case Manager interaction reports)
   - Same treatment: add an "Organization" row sourced from the case manager's `profiles.organization_id` (look up name in the existing report hook — see step 6). Header shows case manager's org name; footer shows the unified "Generated by Evolve Foundation" attribution; CSV gets an Organization + Generated By row.

5. **`src/lib/wellbeingExport.ts`** (Check-ins and Post-Grad Plan PDFs)
   - Update the shared `header()` helper to take an optional `orgName`. When supplied, the header shows org name as the brand line and the report title underneath; when omitted, falls back to current "Evolve Foundation" heading (used by the student's own self-download where org context isn't available without extra fetches).
   - Add a single-line footer drawn on save: `Generated by Evolve Foundation • {date}` so the platform attribution appears even on these PDFs.
   - Update call sites in `src/pages/StudentDetail.tsx` (staff downloads) to pass the student's org name (already available from the loaded profile). Student self-downloads in `StudentCheckIn.tsx` / `PostGraduationPlan.tsx` remain unchanged in behavior but get the new footer automatically.

6. **`src/hooks/useInteractionReport.ts`**
   - Add `organization: { id, name } | null` to the report shape, derived from the case manager's profile org. One extra org-name lookup reusing the same pattern.

### On-screen preview

7. **`src/components/reports/StudentReportPreview.tsx`**
   - Add an "Organization" line in the existing header block above the student name when `data.organization` is set: small muted label "Organization · {name}".
   - Add a small footer-style line at the bottom of the preview: muted "Generated by Evolve Foundation · {generated date}". This mirrors the PDF for parity when staff screenshot or print from browser.

8. **Interaction Report preview (if rendered separately)** — only adjust if it already has a header component analogous to `StudentReportPreview`. No new pages.

## Non-goals (will not touch)

- RLS, migrations, or new tables/columns. Org name is read via existing `training_organizations` SELECT policy.
- Logo upload UI or storage bucket.
- Edge-function PDFs (`request-pdf.ts`, `participant-record-pdf.ts`) — out of scope; this request is about progress reports / dashboards / summaries. Can be done in a follow-up if desired.
- Dashboard widgets — they already show live counts; no branding is generated server-side. The phrase "dashboards" in the request is interpreted as "exported reports that summarize dashboard data", which is covered by the Student Progress + Interaction exports above.

## Verification

- Run a single-student report as Admin → header shows that student's org, footer shows "Generated by Evolve Foundation".
- Filter to one org, bulk export PDF → cover lists that org; per-student pages show their own org.
- Filter to multiple orgs, bulk export → cover reads "Multiple organizations (N)".
- CSV exports open in Excel and show the new `Report Details` block including `Generated By = Evolve Foundation`.
- Check-in and Post-Grad Plan PDFs from `StudentDetail` show the student's org name in the header band.
